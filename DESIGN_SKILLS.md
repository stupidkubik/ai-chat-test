# Навыки для дизайна интерфейса чата

Дата исследования: 25 сентября 2026. Это отдельная заметка о визуальном проектировании; технические требования и архитектура остаются в [DESIGN.md](./DESIGN.md). Для D01 Impeccable установлен локально в `.agents/skills/impeccable`; артефакты дизайна находятся в `docs/ui/`.

## Что должен дать навык именно нам

Для одностраничного чата нужен быстрый переход от идеи к понятному экрану: иерархия сообщений и формы, пустое состояние, генерация, остановка, ошибка, мобильная ширина и заметный фокус клавиатуры. Итог должен быть реализуем в небольшом React-компоненте и CSS, чтобы кандидат мог объяснить код на собеседовании. Качество не равно количеству эффектов или готовых компонентов.

Критерии выбора: (1) помогает принять конкретное визуальное решение до написания CSS; (2) помогает проверить удобство и доступность после реализации; (3) поддерживает Codex; (4) не требует сложного стека или большого подготовительного этапа; (5) имеет проверяемый первоисточник. Популярность GitHub-репозитория — сигнал распространённости, но не доказательство качества результата.

На дату поиска у самостоятельных репозиториев [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) около 130 тыс. звёзд, у [Impeccable](https://github.com/pbakaus/impeccable) около 71 тыс. `frontend-design` расположен внутри большого репозитория Claude Code, поэтому число звёзд этого репозитория нельзя выдавать за популярность отдельного навыка.

## Рекомендация

**Взять Impeccable как один основной навык** и ограничить его применение тремя действиями:

Фактическая настройка D01: навык установлен из [`pbakaus/impeccable`](https://github.com/pbakaus/impeccable/tree/main/.agents/skills/impeccable) через `skill-installer` в папку проекта. Папка `.agents/` исключена из Git: это локальный инструмент процесса, а не зависимость приложения. Для повторной установки использовать `install-skill-from-github.py --repo pbakaus/impeccable --path .agents/skills/impeccable --dest .agents/skills` из системного навыка `skill-installer`. Скрипт запуска `scripts/impeccable` может требовать восстановления исполняемого бита после скачивания. Контекст Impeccable был прочитан; механический `detect` применён к прототипу. Полный workflow `init` не проводился: продуктовые факты уже зафиксированы в `TASK.md` и `DESIGN.md`, а D01 требует передаваемый макет, не отдельную анкету.

1. `shape`: до реализации получить одну схему экрана и состояния, список решений по сетке, типографике, цвету и поведению на телефоне. На это отвести примерно 20–30 минут.
2. После работающего чата — `audit` для клавиатуры, мобильной ширины, читаемости, ошибок и загрузки.
3. Если код/экран стал сложнее необходимого — `distill`; принять только те правки, которые сохраняют требования и понятны кандидату.

Не запускать полный набор команд ради демонстрации навыка. Установка навыка не должна добавлять в приложение библиотеку компонентов. Перед установкой проверить, какие файлы он добавит в проект; по документации Impeccable в Codex может добавить `.agents/skills/` и `.codex/hooks.json`. Не смешивать их автоматически с кодом тестового задания без просмотра diff.

Если хочется минимальной подготовки, альтернативой будет **Anthropic frontend-design для визуального направления + уже доступные правила Vercel для ревью**. Это легче, но две раздельные инструкции придётся сочетать вручную.

## Короткое задание для выбранного навыка

> Спроектируй один рабочий экран текстового AI-чата для десктопа и телефона. Пользователь должен сразу видеть историю и форму. Покажи пустое состояние, генерацию, частичный остановленный ответ, 429 и обрыв сети. Предложи одну узнаваемую, спокойную визуальную систему: сетка, два уровня типографики, цвета, радиусы, отступы и состояние фокуса. Сохрани контрастный `:focus-visible`; не добавляй лендинг, боковую панель, выбор модели, декоративные карточки, тяжёлые анимации или новые зависимости. Результат должен переноситься в простой React + CSS и быть объяснимым начинающему разработчику.

Результат первого прохода сохранить отдельной краткой спецификацией: схема десктопной и мобильной компоновки, набор токенов, перечень интерактивных состояний. В код идти после проверки этого результата человеком.

## Что считать хорошим итогом дизайна

- На 390 px поле, отправка и остановка доступны без горизонтального скролла.
- В пустом состоянии понятно, что делать, и на экране сразу есть поле ввода.
- При генерации статус виден, но не конкурирует с текстом ответа.
- Ошибка имеет конкретное действие для пользователя; ранее полученный текст не теряется.
- Фокус клавиатуры заметен; цвет не единственный носитель смысла.
- Визуальная система выражается в нескольких CSS-переменных и повторяемых правилах, а не в десятках уникальных исключений.
