# D01 — отдельное задание дизайн-агенту

## Контекст

Это тестовое задание на позицию junior. Продукт — одна страница чата с ИИ. Исходный бриф — [`TASK.md`](../../TASK.md), принятые технические рамки — [`DESIGN.md`](../../DESIGN.md), исследование дизайн-навыков — [`DESIGN_SKILLS.md`](../../DESIGN_SKILLS.md). Дизайн должен быть качественным, но воспроизводимым обычным React/CSS без тяжёлой библиотеки и сложной анимации.

Задача выполняется **до** разработки интерфейса. Нужен один целостный вариант, который можно оценить и передать UI-агенту. Не создавай приложение и не подключай API.

## Что сделать

1. Разбери нужные действия пользователя: написать запрос, отправить, видеть поток, остановить, продолжить диалог, понять ошибку. Отрази их в композиции страницы.
2. Предложи чёткую визуальную концепцию с названием, 2–3 референсами или описанием их конкретных приёмов. Не копируй бренд другого сервиса. Кратко объясни, почему она подходит для тестового junior-проекта.
3. Создай статический HTML/CSS-прототип `docs/ui/preview.html` без зависимости от приложения. Он должен показывать реальный основной экран с примером короткого диалога. Для переключения состояний можно использовать простые статические блоки или отдельный раздел файла — без рабочей логики чата.
4. Сохрани снимки прототипа `docs/ui/desktop.png` (1440×900) и `docs/ui/mobile.png` (390×844). Проверяющий должен увидеть оба без запуска проекта.
5. Напиши `docs/ui/UI_SPEC.md` — достаточно точный контракт для UI-агента: структура, размеры/отступы, типографика (включая кириллицу), цвета, границы/тени, адаптивные правила, текст кнопок/подсказок, поведение скролла и фокуса. Укажи токены CSS в таблице или небольшом кодовом блоке.
6. Опиши состояния: пустой чат, печать пользователя, ожидание первого чанка, потоковый ответ, остановлено, успешно завершено, 429, сеть недоступна, ошибка после части ответа. Для каждого укажи видимый текст, доступные действия и как не потерять уже полученный ответ.
7. Укажи доступность: контраст текста, видимый focus ring, логичный Tab, Enter для отправки, Shift+Enter для новой строки и Esc для остановки, названия и размеры кнопок, умеренный `aria-live` для ответа без озвучивания каждого символа. Учти длинные строки и мобильную клавиатуру.
8. Запиши в `WORKLOG.md`, чем помог ИИ и какие предложения были приняты/исправлены. Если применяешь навык из `DESIGN_SKILLS.md`, назови его и зафиксируй конкретный вклад. Отсутствие навыка не блокирует работу.

## Ограничения

- Один экран, без авторизации, списка чатов, настроек, маркетингового лендинга и дополнительных страниц.
- Без обязательных внешних картинок, икон-пакетов и платных шрифтов. Предпочтительны системные шрифты либо бесплатный шрифт с кириллицей и запасным стеком.
- Основной сценарий должен читаться при 390 px и масштабировании 200%.
- Красота не должна прятать кнопку Stop, текст ошибки или фокус клавиатуры.
- Изменения в `TASK.md` и технических решениях `DESIGN.md` не делай молча: предложи их координатору отдельно с причиной.

## Критерии приёмки

- В репозитории есть три названных артефакта; `preview.html` открывается напрямую в браузере.
- Два снимка соответствуют фактическому прототипу, на мобильном нет горизонтального скролла или перекрытых кнопок.
- UI-агент может реализовать экран без вопросов о цветах, отступах, состояниях, подписи действий и адаптивном поведении.
- В `UI_SPEC.md` явно описаны все обязательные состояния и действия из брифа.
- Решение выглядит цельным, доступным с клавиатуры и технически посильно для junior.

## Передача результата

Передай координатору пути трёх артефактов, 3–5 ключевых решений, результаты проверки размеров/клавиатуры, известные компромиссы и запись в `WORKLOG.md`. Если нужен выбор человека между вариантами, сначала всё равно подготовь один рекомендуемый готовый вариант и конкретно сформулируй альтернативу.

### Готовый промпт агенту

> Выполни задачу D01 из `docs/tasks/D01-design.md` в текущем репозитории. Сначала прочитай `TASK.md`, `DESIGN.md`, `DESIGN_SKILLS.md` и `EXECUTION_PLAN.md`. Создай `docs/ui/UI_SPEC.md`, `docs/ui/preview.html`, снимки 1440×900 и 390×844. Проверь их в браузере и обнови `WORKLOG.md` фактическими действиями. Не создавай приложение и не подключай API. Передай результат по формату из `EXECUTION_PLAN.md`.
