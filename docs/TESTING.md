# Локальный mock OpenRouter

Макет в `tests/mock-openrouter.mjs` принимает совместимый `POST /api/v1/chat/completions` на `127.0.0.1`. Он не обращается в интернет, не требует ключа и не записывает сообщения в лог. Подготовлен в T03 и используется на этапах A05, C06 и Q07.

## Запуск и автоматическая проверка

```bash
npm ci
npm test
npm run mock:openrouter
```

`npm test` запускает встроенный `node:test` на динамическом порту. Проверяются статус и события успешного SSE, ответ 429, разрывы до и во время ответа, задержки и закрытие соединения после отмены. Ключ OpenRouter не нужен. `npm run mock:openrouter` слушает только `127.0.0.1:8787`; приложение запускается отдельно через `npm run dev` на порту 3000.

Для ручной проверки в другом терминале:

```bash
curl --no-buffer -i -X POST http://127.0.0.1:8787/api/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -H 'x-mock-scenario: success' \
  -d '{"model":"test:free","stream":true,"messages":[{"role":"user","content":"Привет"}]}'
```

Ожидается `200`, `Content-Type: text/event-stream`, три `data:` события с `choices[0].delta.content` и `data: [DONE]`. Первое событие намеренно отправляется двумя записями, поэтому клиент обязан собирать SSE независимо от границ сетевых чанков.

Для сценариев замените значение `x-mock-scenario`:

| Сценарий | Наблюдение |
| --- | --- |
| `rate-limit` | HTTP 429 и JSON с `error.message` |
| `network-failure` | Соединение закрывается до HTTP-ответа |
| `midstream-disconnect` | Первый `data:` приходит, затем поток обрывается без `[DONE]` |
| `slow` | Первый байт задержан на 600 мс |
| `timeout` | Первый байт задержан на 2000 мс |
| `abort-observed` | Поток остаётся открытым; после отмены клиента терминал макета печатает `Client connection closed after abort` |

Для запуска с одним сценарием по умолчанию используйте серверную переменную, например `MOCK_SCENARIO=rate-limit npm run mock:openrouter`. Заголовок нужен только для прямой ручной проверки макета. Задержки настраиваются при запуске через `MOCK_SLOW_MS`, `MOCK_TIMEOUT_MS`, порт — через `MOCK_PORT`.

## Контракт для A05

Серверный `/api/chat` направляет запрос к `http://127.0.0.1:8787/api/v1/chat/completions` только если **на сервере** выставлен `OPENROUTER_MOCK=1` и `NODE_ENV` не равен `production`. Адрес допускается менять через серверную переменную `OPENROUTER_MOCK_URL` только на loopback (`127.0.0.1` или `localhost`); в production mock-переменные игнорируются, а настоящий `OPENROUTER_API_KEY` обязателен. Сценарий макета задаётся только серверной переменной `OPENROUTER_MOCK_SCENARIO`; заголовок браузера не пересылается. Входящий запрос браузера не выбирает endpoint или сценарий.

Макет ожидает JSON с `messages` и `stream: true`. Он возвращает фрагменты формата OpenRouter `choices[0].delta.content`; завершение определяется только по `[DONE]`. Для проверки UI после A05/C06: успешный ответ нарастает; 429 показывает понятный текст; разрыв оставляет уже полученный фрагмент с ошибкой; Stop закрывает поток и возвращает активную форму; таймаут не оставляет бесконечного индикатора.

Маршрут `/api/chat` принимает только JSON с `messages`; у каждого сообщения допустимы только `role` (`user` или `assistant`) и непустой текстовый `content`. Первая и последняя записи должны быть пользовательскими. Ограничения: 20 сообщений, 4000 символов на сообщение и 20000 символов суммарно. Модель фиксирована в серверном коде как `openrouter/free`, поэтому браузер не может выбрать платную модель. Этот официальный router направляет запрос к одной из доступных бесплатных моделей.

Upstream ограничен 45 секундами без новых байтов и 90 секундами общей длительности. Байты SSE, в том числе комментарии keep-alive, обновляют таймер бездействия. До начала ответа таймаут возвращает HTTP 504; после начала потока маршрут отправляет `event: error` с кодом `timeout`. HTTP 429 и SSE-ошибки провайдера нормализуются в безопасные сообщения без сырого текста ответа. Обрыв до `[DONE]` сохраняет полученные события и завершает поток событием `network_error`. В `app/api/chat/route.ts` задан `maxDuration` 120 секунд; `vercel.json` включает поддержку отмены для этой Node.js функции.

Для локального режима скопируйте `.env.example` в `.env.local` и раскомментируйте mock-переменные. Запустите `npm run mock:openrouter` и `npm run dev` в отдельных терминалах. Сценарии `rate-limit`, `midstream-disconnect` и `abort-observed` можно задавать переменной `OPENROUTER_MOCK_SCENARIO`; входящие заголовки браузера её не меняют. В production mock-настройки игнорируются, а без настоящего `OPENROUTER_API_KEY` маршрут возвращает безопасную ошибку конфигурации.

Для реального OpenRouter уберите `OPENROUTER_MOCK` и mock-переменные из серверного окружения, заполните `OPENROUTER_API_KEY` в локальном `.env.local` и запустите приложение. Не передавайте ключ в URL, браузерный запрос или этот документ.

## Ограничения

Макет проверяет транспорт и реакции приложения, но не повторяет все поля ответов OpenRouter и не подтверждает доступность бесплатной модели. 25.09.2026 live-запрос через `/api/chat` с настроенным ключом вернул HTTP 200, SSE с текстовым фрагментом и `[DONE]`. Перед сдачей повторить живую проверку; отмену также проверить на выбранном хостинге.
