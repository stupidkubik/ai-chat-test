# D01 — сверка с исходным брифом

Источник: [TASK.md](../../TASK.md). Здесь «учтено в дизайне» означает, что UI-агент получил конкретный экран, текст или правило поведения. Это не доказательство, что функция уже работает: приложение ещё не создано. Состояния описаны в [UI_SPEC.md](./UI_SPEC.md), рабочий пример — в [preview.html](./preview.html), пустой экран — [empty-mobile.png](./empty-mobile.png).

| Требование брифа | Дизайн D01 | Проверка после реализации |
| --- | --- | --- |
| Один веб-чат, вопрос и ответ модели | Один экран с историей и формой; без лишней навигации. | S02/U04: рабочий React-экран; A05: ответ OpenRouter. |
| Бесплатная модель OpenRouter `:free` | UI не предлагает платную модель и не обещает конкретное имя до выбора доступной модели. | A05/P09: выбрать и проверить актуальный `:free` ID живым запросом. |
| Потоковый вывод и индикатор генерации | Текущий частичный ответ и «Ассистент отвечает» показаны в прототипе. | C06/Q07: несколько чанков должны появиться до завершения запроса. |
| «Стоп», частичный текст остаётся, UI снова готов | Есть видимая кнопка и состояния остановки до/после первого чанка; текст сохраняется по контракту. | C06/Q07: проверить отмену, повторный ввод и серверное прекращение запроса. |
| 429, таймаут, обрыв сети | Для каждого задан текст и выход из ожидания; в прототипе есть отдельные примеры, включая ошибку после части ответа. | C06/Q07: воспроизвести все три причины на mock API; проверить отсутствие вечного индикатора. |
| История в рамках сессии и решение о reload | История видна; под формой сказано, что она исчезнет после обновления. Причина выбора записана в `DESIGN.md`. | C06/Q07: память вкладки и очищение после reload. |
| Секрет не в браузере | UI не содержит ключа; архитектурное решение описано в `DESIGN.md`. | A05/P09: серверный маршрут, Network и клиентский бандл без ключа. |
| React/Vue | Прототип самостоятельный HTML/CSS, будущий стек — React/Next.js по `DESIGN.md`. | S02/U04: реализовать компоненты и стили. |
| Tab, Enter, Esc, семантика | История теперь `ol/li`, форма — `form/label/textarea/button`; порядок и клавиши описаны в спецификации. | U04/C06/Q07: реальная отправка Enter, перенос Shift+Enter, Stop по Esc, фокус и скринридер. |
| Адаптивность и мобильный ввод | Снимки 1440×900, 390×844 и пустого состояния 390×844; форма остаётся видимой. | U04/Q07: телефон, длинный текст, 200% масштаб, виртуальная клавиатура. |
| Пустое состояние | Полный экран доступен через `preview.html?state=empty` и показан на отдельном снимке. | U04/Q07: показать до первого сообщения и скрыть после отправки. |
| Убрать стандартный outline | Браузерный стиль заменён контрастным кольцом 3 px, не убран фокус как таковой. | U04/Q07: проверить Tab в нескольких браузерах; объяснить решение в README. |
| Markdown и тёмная тема | Необязательные бонусы сознательно отложены. | R08: зафиксировать как дальнейшие шаги, если не реализованы. |
| Ветки, коммиты, PR и merge | D01 ведётся в `codex/d01-design`, [PR #1](https://github.com/stupidkubik/ai-chat-test/pull/1) открыт. | После проверки дизайна слить PR; повторить процесс для следующих этапов. |

## Вывод

Для передачи UI-этапу теперь есть визуальный пример активного и пустого чата, тексты всех обязательных ошибок и правила клавиатуры. Пока **не подтверждены работающие функции**: OpenRouter, безопасность ключа, поток, отмена, сохранение истории и обработка ошибок. Их статус нельзя считать «готово» по статическому прототипу; проверки назначены следующим этапам.
