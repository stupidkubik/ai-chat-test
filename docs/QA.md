## Команды и ограничения

- `npm test`: 24/24. Первая попытка в sandbox завершилась `listen EPERM` на `127.0.0.1`; повторный запуск с разрешённым loopback прошёл.
- `npm run lint`, `npm run typecheck`, `npm run build`: успешно. Build — Next.js 16.3.6, `/` статический, `/api/chat` динамический.
- `vercel inspect` подтвердил targets, `vercel env ls` — только область секрета, `vercel logs` — запросы `/api/chat` без серверных исключений; сырые пользовательские сообщения и секреты в отчёт не переносились.
- Реальное закрытие вычисления у провайдера после Stop не видно со стороны приложения. Проверено закрытие браузерного потока и возобновление работы UI; unit-тест подтверждает закрытие соединения с mock.
- На физическом телефоне и с виртуальной клавиатурой проверка не проводилась. Изолированный Chromium не может пройти защиту Vercel без авторизации.

**Вывод Q07:** функциональные сценарии на фактическом Production работали; ссылка из запроса указывала на Preview без ключа и возвращала 500. На тот момент для внешнего проверяющего ещё требовался адрес без Vercel Login. Повторная проверка адреса — ниже, в P09.

## P09 — заключительная проверка, 26.09.2026

После слияния R08 (`39f9899`) проверены публичный репозиторий и локальный запуск по README. `npm ci` восстановил зависимости из lockfile, `npm run dev` открыл страницу на `localhost:3000` с уже настроенным локальным `.env.local`. Значение ключа не выводилось. Живой POST через локальный `/api/chat` вернул HTTP 200, `text/event-stream`, 152 SSE-события, `[DONE]` и ни одного события ошибки. Второй локальный запрос отменён после первого полученного чанка; `AbortController` подтвердил состояние aborted. Текст ответов в журнал не записывался.

В изолированном Chromium [основной адрес](https://ai-chat-test-lake.vercel.app/) открыл приложение без входа в Vercel. Первый живой ответ завершился; на ширине 390 px длинный ответ шёл потоком. Esc после появления текста дал статус «Ответ остановлен», сохранил 8957 символов фрагмента; через 1,5 секунды длина не изменилась, форма стала активной. Горизонтального переполнения не было, консоль — 0 ошибок и предупреждений. Следующий запрос после этого большого частичного ответа не дал первого байта за 30 секунд и был остановлен Esc; успешное продолжение после Stop уже было проверено в Q07, но в P09 повторно не подтверждено. Проверка браузерного запроса показала `POST /api/chat` без заголовков Authorization и ключа провайдера.

Эта проверка подтверждает доступность и работу адреса на 26.09.2026, но не гарантирует доступ из всех сетей или будущую доступность бесплатной модели. Исходные ограничения Q07 по физическому телефону, скринридеру и Preview сохраняются.

Финальные команды на ветке P09: `npm test` — 24/24, `npm run lint`, `npm run typecheck`, `npm run build`, `git diff --check` — успешно. Production build оставил `/` статическим, а `/api/chat` динамическим. Локальный dev-запуск временно переписал генерируемый `next-env.d.ts` на dev-пути; последующий production build восстановил исходные пути, файл не попал в diff.
